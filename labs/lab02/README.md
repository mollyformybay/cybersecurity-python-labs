# Лабораторна робота №2. Розробка консольних утиліт для задач кібербезпеки

## Варіант 15: Аудитор логів використання привілейованих команд (Sudo / Privileged Access)

### 1. Структура файлів варіанта
Вхідні файли розміщено в підкаталозі `labs/lab02/data/data_v15/`:
* `sudo.log` — журнал подій виклику утиліти `sudo` (часові мітки ISO 8601, імена користувачів, TTY, робочі директорії, цільові користувачі та виконані команди).
* `alert_commands.txt` — словник сигнатур/патернів підозрілих або високризикових команд (наприклад: `chmod 777`, `nc`, `nmap`, `dd`, `/etc/shadow`).

### 2. Встановлення залежностей
Переконайтеся, що активовано віртуальне середовище, та встановіть залежності проєкту:
pip install -r requirements.txt

### 3. Приклади команд запуску

#### Демонстрація Завдання 1 (Об'єктно-орієнтоване програмування)
Демонструє створення користувачів, безпечне хешування паролів за допомогою `PBKDF2-HMAC-SHA256`, контроль сесій, таймаути та аудит подій:
python -m labs.lab02.main demo

#### Запуск аналізу логів sudo (Завдання 2)
Аналіз журналу `sudo.log`, виявлення небезпечних операцій та експорт аудиторського звіту в форматі JSON:
python -m labs.lab02.main analyze --sudo-log labs/lab02/data/data_v15/sudo.log --alert-commands labs/lab02/data/data_v15/alert_commands.txt --out-json labs/lab02/data/sudo_audit_report.json

Також можливий прямий автономний виклик модуля `task2`:
python -m labs.lab02.task2 --sudo-log labs/lab02/data/data_v15/sudo.log --alert-commands labs/lab02/data/data_v15/alert_commands.txt --out-json labs/lab02/data/sudo_audit_report.json

### 4. Опис параметрів CLI (`analyze` / `task2`)
* `--sudo-log` (Path, обов'язковий) — шлях до цільового текстового журналу `sudo.log`.
* `--alert-commands` (str) — шлях до файлу зі списком підозрілих патернів або команди через кому (за замовчуванням: `chmod 777,nc,nmap,dd,/etc/shadow`).
* `--out-json` (Path) — шлях для збереження підсумкового звіту в JSON.
* `--log-level` (str) — рівень деталізації логування (`DEBUG`, `INFO`, `WARNING`, `ERROR`). За замовчуванням `INFO`.

### 5. Обробка помилок та виняткових ситуацій
* **Відсутність вхідного файлу**: Перевіряється через `pathlib.Path.exists()`, подія логується як `ERROR`, після чого утиліта коректно завершує роботу з кодом 1.
* **Некоректний синтаксис рядків журналу**: Рядки, що не відповідають регулярному виразу, фіксуються в рівні `DEBUG` без зупинки процесу аналізу та підраховуються у статистиці.
* **Валідація вхідних даних моделі ООП**: Порушення формату email призводить до виклику `ValueError`, а спроби несанкціонованого доступу до приватних ключів хешу або солі пароля блокуються винятком `KeyError`.

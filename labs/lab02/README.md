## Завдання 1

Реалізовано модель облікового запису:

- User — користувач із перевіркою email та хешуванням пароля.
- Admin — успадковує User і керує дозволами.
- Session — контролює час активності сесії.
- AuditLog — зберігає записи про спроби входу та вихід.
- UserAccount — поєднує користувача, сесію і журнал аудиту.

Паролі хешуються за допомогою PBKDF2-HMAC-SHA256 із випадковою сіллю.
Час подій зберігається в UTC. Таймаут сесії — 900 секунд.

Запуск демонстрації:

```bash
python -m labs.lab02.main demo
```

## Завдання 2

Утиліта аналізує журнал sudo та:

- виділяє час, користувача, TTY, робочий каталог, цільового користувача і команду;
- підраховує команди, виконані від імені root;
- знаходить команди за правилами з файла або списку;
- формує статистику за користувачами;
- виводить попередження та зберігає JSON-звіт.

### Вхідні дані

Навчальні файли варіанта 15 потрібно розмістити в:

```text
labs/lab02/data/data_v15/
```

Часові мітки в `sudo.log` мають бути у форматі ISO 8601 із часовим поясом.

Приклад рядка:

```text
2026-09-27T09:20:00+03:00 host01 sudo: carol : TTY=pts/2 ; PWD=/tmp ; USER=root ; COMMAND=/usr/bin/chmod 777 /srv/share
```

Вміст `alert_commands.txt`:

```text
chmod 777
nc
nmap
dd
/etc/shadow
```

Кожне правило записується в окремому рядку.
Порожні рядки та коментарі, що починаються з `#`, пропускаються.

Правила описують назви команд, аргументи або їх послідовності, а не довільні регулярні вирази.

### Запуск аналізу

З типовими шляхами:

```bash
python -m labs.lab02.main analyze
```

З усіма параметрами:

```bash
python -m labs.lab02.main analyze --sudo-log labs/lab02/data/data_v15/sudo.log --alert-commands labs/lab02/data/data_v15/alert_commands.txt --out-json labs/lab02/data/sudo_audit_report.json --log-level INFO
```

Передавання правил списком:

```bash
python -m labs.lab02.main analyze --alert-commands "chmod 777,nc,nmap,dd,/etc/shadow"
```

Усі команди потрібно виконувати з кореня репозиторію, де розташовані каталоги `labs` і `shared`.

### Параметри командного рядка

| Параметр | Опис | Типове значення |
|---|---|---|
| `--sudo-log` | Шлях до журналу sudo | `labs/lab02/data/data_v15/sudo.log` |
| `--alert-commands` | Файл правил або список через кому | `labs/lab02/data/data_v15/alert_commands.txt` |
| `--out-json` | Шлях до JSON-звіту | `labs/lab02/data/sudo_audit_report.json` |
| `--log-level` | DEBUG, INFO, WARNING або ERROR | INFO |

### Результат

JSON-звіт містить:

- `summary` — кількість команд, запусків від імені root, некоректних рядків і підозрілих команд;
- `top_users` — статистику команд і спрацювань за користувачами;
- `alerts` — підозрілі записи та правила, які спрацювали.

Для наданих навчальних даних варіанта 15 очікується:

```text
total_commands: 12
root_executions: 10
malformed_lines: 0
high_risk_commands: 7
```

Спрацювання правила означає необхідність перевірки команди, а не підтвердження атаки.

## Обробка помилок

- Відсутній журнал або файл правил — повідомлення ERROR і код завершення 1.
- Порожній список правил — повідомлення ERROR і код завершення 1.
- Помилка читання або запису файла — повідомлення ERROR і код завершення 1.
- Некоректний рядок журналу або дата — попередження WARNING; рядок пропускається та враховується в `malformed_lines`.
- Неправильні аргументи командного рядка — повідомлення argparse і код завершення 2.
- Некоректний email — ValueError.
- Невідомий ключ облікового запису — KeyError.
- Неправильний тип значення при присвоєнні через ключ — TypeError.

Успішне виконання завершується з кодом 0.

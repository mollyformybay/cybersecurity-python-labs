## Предметна область

Реєстр ризиків налаштування робочих станцій.

Застосунок зберігає навчальні знахідки аудиту за напрямами:

- updates — оновлення;
- permissions — права доступу;
- protection — захист.

Поля знахідки:

- id — ідентифікатор, створений SQLite;
- code — унікальний код;
- title — назва знахідки;
- category_id — ідентифікатор категорії;
- value — навчальна оцінка ризику від 0 до 10;
- status — стан опрацювання: new, in_progress або done.

Одиниця вимірювання — score. Поріг ризику — 8.0.
Для вибірки записів за порогом використовується min_value=8.

## Приклади читання

У браузері або Swagger UI:

```text
GET /ping
GET /student
GET /categories
GET /records
GET /records?min_value=8
GET /records?category_id=1&status=new
GET /records?limit=2&offset=2
GET /records/1
```

Параметри списку:

- category_id — додатний ідентифікатор категорії;
- status — один із дозволених статусів;
- min_value — мінімальна оцінка від 0 до 10;
- q — буквальний підрядок назви з урахуванням регістру;
- limit — від 1 до 100, типово 20;
- offset — не менше 0, типово 0.

Фільтри поєднуються через AND. Результати сортуються за id.
Символи % та _ у параметрі q не є шаблонами.

## Створення знахідки

У Swagger UI виконати POST /records із тілом:

```json
{
  "code": "V15-DEMO",
  "title": "Навчальна знахідка",
  "category_id": 1,
  "value": 8.5,
  "status": "new"
}
```

Очікувана відповідь — 201 із створеним id та category_name.

Для GET, PUT і DELETE використати id із відповіді.
У PUT необхідно передати всі п'ять змінюваних полів.
Передавати id у тілі створення або оновлення заборонено.

Повторне використання зайнятого code повертає 409.

## Пакетне додавання та rollback

POST /records/bulk приймає масив із 1–100 знахідок.

Приклад пакета з дублікатом початкового коду:

```json
[
  {
    "code": "V15-ROLLBACK-01",
    "title": "Перевірка скасування пакета",
    "category_id": 1,
    "value": 8.5,
    "status": "new"
  },
  {
    "code": "V15-01",
    "title": "Дублікат наявного коду",
    "category_id": 2,
    "value": 5.0,
    "status": "new"
  }
]
```

За наявності V15-01 очікується 409.
Перший елемент також не повинен зберегтися.

Після запиту перевірити відсутність першого запису та
незмінну кількість записів. Під час підрахунку враховувати
пагінацію: limit до 100 і наступні сторінки через offset.

Усі вставлення пакета виконуються в одній транзакції.
Помилка будь-якого елемента скасовує весь пакет.

## Перевірка даних і помилки

- 200 — успішне читання або оновлення;
- 201 — успішне створення;
- 204 — успішне видалення без тіла відповіді;
- 404 — запис або потрібну категорію не знайдено;
- 409 — повторний код, назва категорії або видалення
  непорожньої категорії;
- 422 — некоректні поля чи параметри;
- 500 — технічна помилка роботи бази.

Pydantic перевіряє довжини рядків, оцінки, статуси,
ідентифікатори та невідомі поля.
NaN і нескінченні оцінки заборонені.

## Організація роботи з базою

SQL розміщено в repository.py.
Значення передаються через параметри ?, без вставлення
користувацьких значень у текст SQL.

Читання знахідок використовує JOIN із categories.
Для кожного з'єднання вмикається PRAGMA foreign_keys = ON.

Контекст with connection підтверджує або скасовує зміни.
closing закриває з'єднання після операції.
Шлях до бази визначається відносно database.py.
